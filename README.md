# Google Play Market Scraper TEST ASSIGNMENT

Консольний застосунок на C# для збору `package name` додатків з Google Play Market за ключовим словом та кодом країни.

Проєкт розроблено згідно з вимогами тестового завдання. Код написаний на **.NET 9.0** з використанням принципів чистої архітектури, Dependency Injection та правильного управління `HttpClient`.

## Результати дослідження

Під час виконання завдання я проаналізував роботу внутрішнього API Google Play та з'ясував наступне:

### 1. Параметри URL
Аналізуючи запити до `https://play.google.com/_/PlayStoreUi/data/batchexecute`, я виявив, що більшість query-параметрів у URL є статичними і їх можна захардкодити.
* Єдиний параметр, що постійно змінюється з кожним новим унікальним запитом — це `_reqid`.
* Проте, під час тестування стало зрозуміло, що для успішного виконання запиту більшість цих параметрів взагалі не є обов'язковими.
* **Як передається країна:** Регіон пошуку визначається виключно через query-параметр `hl` (наприклад, `?hl=us`). Усю іншу логіку та параметри пошуку Google вимагає передавати безпосередньо в тілі запиту.

### 2. Тіло запиту (Request Body)
* **Content-Type:** Запит відправляється у форматі `application/x-www-form-urlencoded`.
* **Як передається ключове слово:** Тіло запиту містить виклики двох внутрішніх RPC-методів (`AZO9Cb` та `lGYRle`). Ключове слово для пошуку (`keyword`) та ідентифікатор пристрою (`android id`) зашиті всередині параметрів цих методів.
* **Як змінюється тіло:** При зміні ключового слова ми просто підставляємо нове значення у відповідне місце в шаблоні запиту. Логічно, що зміна ключового слова ініціює пошук нових результатів. Для зручності підтримки я виніс цей складний шаблон у зовнішній файл `Templates/SearchRequest.txt`, щоб не забруднювати код хардкодом.

### 3. Парсинг відповіді
Сервер повертає дані у дуже специфічному "брудному" форматі (суміш масивів та екранованого JSON).
* **Де знаходяться package name:** Я знайшов закономірність, що всі назви пакетів знаходяться поруч зі строкою `\",7]`. Оскільки структура відповіді нестандартна, я вирішив використати регулярні вирази (Regex).
* Цей патерн я написав з допомогою ШІ  `(?<=\\\"")[A-Za-z][A-Za-z0-9_]*(?:\.[A-Za-z0-9_]+)+(?=\\\"")` він надійно знаходить класичний формат назви пакета (мінімум два слова, розділені крапкою).
* **Як зберегти порядок:** Сервер віддає додатки у певному порядку. Щоб не втратити цю послідовність (як це сталося б при використанні `HashSet`), я застосував `LINQ`. Фільтрація дублікатів та збереження оригінального порядку реалізовані через ланцюжок `.Where() -> .Select() -> .Distinct() -> .ToList()`.

## Технічні деталі реалізації
* **Стек:** C#, .NET 9.0.
* **HttpClient:** Клієнт зареєстрований через `IHttpClientFactory` (`AddHttpClient`), що є best-practice для уникнення проблеми вичерпання сокетів (socket exhaustion).
* **Конфігурація:** Усі налаштування (Base URL, Android ID, шляхи до шаблонів) винесені в `appsettings.json`.
* **Обробка помилок:** Реалізовано глобальний блок `try-catch`, який коректно відловлює проблеми з мережею (`HttpRequestException`), відсутність файлів шаблонів (`FileNotFoundException`, `InvalidOperationException`) та помилки парсингу (`ScraperException`).
* **Логування:** Використовується `Microsoft.Extensions.Logging` для інформативного відстеження процесу роботи.

## Як запустити

```bash
   dotnet run -- "ваше_слово" "код_країни"
 ```
